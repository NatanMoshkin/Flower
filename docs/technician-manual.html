167_01 Saad — Flower

Technician's manual

מדריך לטכנאי

The detailed reference: sequence, error codes, settings, IO, robot protocol, diagnostics and the deviations you need to know about. For day-to-day running see the operator manual.

המדריך המפורט: רצף, קודי תקלה, הגדרות, IO, פרוטוקול רובוט, אבחון והחריגות שחשוב להכיר. להפעלה יומיומית ראה את מדריך המפעיל.

1 · System overview

1 · סקירת המערכת

One device does everything: a Beckhoff CP6606 panel PC running TwinCAT 3. It holds the PLC program and the operator screens (classic PLC visualization). There is no separate HMI box and no PC in the loop.

מכשיר אחד עושה הכל: פאנל CP6606 של Beckhoff המריץ TwinCAT 3. הוא מכיל את תוכנית ה-PLC ואת מסכי המפעיל (ויזואליזציה קלאסית). אין קופסת HMI נפרדת ואין מחשב בלופ.

PartWhat it is
MAINRuns every scan. Forces the machine mode onto all eight pistons, reads the push buttons, drives the lamps, and translates the robot's commands.
FB_MasterAutoCycleThe sequence. One state machine, 19 assigned states.
FB_SolSpringPiston_2PosOne instance per actuator, eight in total. Single coil, spring return.
PRG_IoMapCopies raw IO to named aliases. Runs on its own 5 ms task, which pre-empts the 10 ms PLC task.
FB_RobotTcpClientThe PLC is the TCP client; the robot is the server on port 6001.
חלקמה זה
MAINרץ בכל סריקה. כופה את מצב המכונה על שמונה הבוכנות, קורא את הלחצנים, מפעיל את הנוריות, ומתרגם את פקודות הרובוט.
FB_MasterAutoCycleהרצף. מכונת מצבים אחת, 19 מצבים.
FB_SolSpringPiston_2Posמופע אחד לכל מפעיל, שמונה בסך הכל. סליל אחד, חזרה בקפיץ.
PRG_IoMapמעתיק IO גולמי לשמות. רץ במשימה נפרדת של 5 מ"ש, הקודמת למשימת ה-PLC של 10 מ"ש.
FB_RobotTcpClientה-PLC הוא לקוח TCP; הרובוט הוא השרת בפורט 6001.
All eight actuators are single-coil spring-return

Energising the coil drives the piston out; de-energising lets a spring pull it home. There is no mid-position and no brake. Power loss, a broken wire or a dead coil all retract — fail-safe by construction. It also means a piston cannot be stopped part-way, which rules out several otherwise-obvious features.

כל שמונה המפעילים הם חד-סליליים עם חזרה בקפיץ

הפעלת הסליל מוציאה את הבוכנה; ניתוקו מאפשר לקפיץ להחזירה. אין מצב אמצע ואין בלם. נפילת מתח, חוט קרוע או סליל מקולקל — כולם מכניסים את הבוכנה. זהו כשל-לבטוח מעצם הבנייה. משמעות נוספת: לא ניתן לעצור בוכנה באמצע התנועה, מה ששולל כמה תכונות מובנות מאליהן.

2 · The Auto sequence

2 · רצף האוטומט

The full picture, clickable state by state, is in the as-built state machine diagram. Summary:

התמונה המלאה, מצב אחר מצב עם לחיצה, נמצאת בתרשים מכונת המצבים כפי שנבנתה. תמצית:

StateValueWhat happens
NOT_HOMED40In Automatic but not armed. Nothing driven, no timer. The power-up state, and where STOP and Manual leave the machine. Only an operator START leaves it.
IDLE0Armed. Waits for the robot's CMD:1, or the operator's two-button hold.
INIT_PUSH/SEP/GRIP_RETRACTING10 / 11 / 12The retract chain: push home, then sep, then grip. Ordering matters — it is a collision constraint. Exits to IDLE when arming, or to CHECK_PLATE when it is the front of a cycle.
CHECK_PLATE20Waits for the plate. Was called WAIT_PLATE; renamed 2026-08-05, wire value unchanged.
GRIP_EXTENDING → GRIP_RETRACTING21, 1, 3, 4, 5, 6, 7, 8, 22The cycle: clamp, sep out, push out, dwell, push back, dwell, sep back, dwell, release. Then IDLE, still armed.
ERR99Latched. Only RESET leaves it — HMI button, orange PB2, or the robot's CMD:2.
RECOVER_PUSH/SEP/GRIP_RETR50 / 51 / 52Fault recovery only. Same motion as the INIT chain but its own identity, so a failed recovery reports 12/13/14 instead of looking like a failed arming. Always exits to IDLE.
מצבערךמה קורה
NOT_HOMED40במצב אוטומטי אך ללא אישור. שום דבר לא מופעל, אין טיימר. זהו מצב ההדלקה, ולשם מגיעים לאחר עצירה או מצב ידני. רק לחיצת התחלה של מפעיל מוציאה ממנו.
IDLE0מאושר. ממתין לCMD:1 מהרובוט, או להחזקת שני הלחצנים על ידי המפעיל.
INIT_PUSH/SEP/GRIP_RETRACTING10 / 11 / 12שרשרת ההכנסה: קודם דחיפה, אחר כך הפרדה, אחר כך תפיסה. הסדר חשוב — זו מניעת התנגשות. יוצא לIDLE בעת אישור, או לCHECK_PLATE כשזו תחילת מחזור.
CHECK_PLATE20ממתין למגש. נקרא בעבר WAIT_PLATE; שונה השם ב-2026-08-05, ערך התקשורת לא שונה.
GRIP_EXTENDING → GRIP_RETRACTING21, 1, 3, 4, 5, 6, 7, 8, 22המחזור: תפיסה, הוצאת הפרדה, הוצאת דחיפה, השהיה, החזרת דחיפה, השהיה, החזרת הפרדה, השהיה, שחרור. אחר כך IDLE, עדיין מאושר.
ERR99נעול. רק איפוס מוציא ממנו — לחצן במסך, לחצן כתום, או CMD:2 מהרובוט.

Two kinds of start, different owners

Operator START (HMI button or green PB3) means home the pistons and arm — it never runs a cycle. Robot CMD:1 means run one cycle, and is only accepted from IDLE. The operator's two-button hold is fed into the same input as CMD:1, because it means the same thing.

שני סוגי התחלה, בעלים שונים

התחלה של מפעיל (לחצן במסך או לחצן ירוק) פירושה אפס מקום ואשר — היא לעולם אינה מריצה מחזור. CMD:1 מהרובוט פירושו הרץ מחזור אחד, ומתקבל רק מIDLE. החזקת שני הלחצנים של המפעיל מוזנת לאותה כניסה כמו CMD:1, כי משמעותה זהה.

With bNoSensors set, almost no error can occur

bNoSensors makes the twelve movement steps advance on their timer instead of on sensors, so codes 1/3/4/5/6/7/8/10/11/12/13/14 all become unreachable — only code 9 can still fire. Every bench test so far has run with this flag set, which means no movement-timeout path has ever been exercised on any panel. Turn it off before production.

כאשר bNoSensors מסומן, כמעט שום תקלה לא יכולה לקרות

bNoSensors גורם לשנים-עשר שלבי התנועה להתקדם לפי הטיימר במקום לפי חיישנים, כך שהקודים 1/3/4/5/6/7/8/10/11/12/13/14 הופכים בלתי ניתנים להשגה — רק קוד 9 עוד יכול לקרות. כל הבדיקות עד כה רצו עם דגל זה מסומן, כלומר אף מסלול פסק-זמן של תנועה לא נבדק מעולם באף פאנל. כבה אותו לפני ייצור.

These survive a power cycle — including the bench flags

The settings are persistent and are flushed to disk about two seconds after you stop editing. That includes bNoSensors and bBypassPlateSensors: a flag left on for a bench session comes back on after a reboot. Check both before running production.

אלה נשמרים לאחר כיבוי — כולל דגלי השולחן

ההגדרות נשמרות ונכתבות לדיסק כשתי שניות לאחר סיום העריכה. זה כולל את bNoSensors ואת bBypassPlateSensors: דגל שהושאר דלוק לבדיקה יחזור דלוק לאחר אתחול. בדוק את שניהם לפני ייצור.

5 · Robot interface

5 · ממשק הרובוט

Raw ASCII over TCP, no newline framing, one send → one reply. The PLC dials the robot; the endpoint is editable on the Robot screen.

ASCII גולמי מעל TCP, בלי מפריד שורה, שליחה אחת → תשובה אחת. ה-PLC מתקשר לרובוט; ניתן לערוך את הכתובת במסך הרובוט.

PLC sendsRobot repliesMeaning
STATE:0CMD:1Armed — run one cycle.
STATE:99CMD:2Faulted — reset it.
anything elseCMD:0Wait. This is why new states cost nothing robot-side: 30, 40, 50, 51, 52 all land here.
ה-PLC שולחהרובוט משיבמשמעות
STATE:0CMD:1מאושר — הרץ מחזור אחד.
STATE:99CMD:2תקלה — אפס אותה.
כל דבר אחרCMD:0המתן. זו הסיבה שמצבים חדשים אינם עולים דבר בצד הרובוט: 30, 40, 50, 51, 52 — כולם נופלים לכאן.
The step numbers are a wire contract

eStep's numeric value goes on the wire, so a state may be renamed freely but never renumbered. 0 and 99 in particular are the protocol.

מספרי המצבים הם חוזה תקשורת

הערך המספרי של eStep נשלח בתקשורת, ולכן ניתן לשנות שם של מצב בחופשיות אך לעולם לא את המספר. במיוחד 0 ו99 — הם עצמם הפרוטוקול.

7 · Known deviations

7 · חריגות ידועות

Grip and plate use OR, not AND

Because GripSolR has no air, the sequence advances when either gripper reports position, and the plate gate passes on either sensor. This is a deliberate decision to keep producing on one gripper. The cost: a genuine failure of one gripper is invisible, and errors 10/11 can only fire when both fail. Treat grip position as unverified in any fault analysis.

תפיסה ומגש משתמשים ב-OR, לא ב-AND

מכיוון שאין אוויר לGripSolR, הרצף מתקדם כאשר אחת מהתפסניות מדווחת על מקום, ושער המגש עובר עם אחד מהחיישנים. זו החלטה מכוונת כדי להמשיך לייצר עם תפסנית אחת. המחיר: כשל אמיתי של תפסנית אחת הוא בלתי נראה, וקודי 10/11 יכולים לקרות רק כאשר שתיהן נכשלות. התייחס למצב התפיסה כלא מאומת בכל ניתוח תקלה.

Plate sensors L and R are swapped

The IO list puts PlateSensR on DI 21 and PlateSensL on DI 22; PRG_IoMap does the opposite. Harmless for the cycle while the gate is an OR, but the L/R lamps on the main screen are therefore mislabelled. Settle which physical side is which before changing either end.

חיישני המגש שמאל וימין הפוכים

רשימת ה-IO ממקמת את PlateSensR ב-DI 21 ואת PlateSensL ב-DI 22; PRG_IoMap עושה את ההפוך. לא מזיק למחזור כל עוד השער הוא OR, אך משמעות הדבר שנוריות L/R במסך הראשי מסומנות שגוי. קבע איזה צד פיזי הוא מה לפני שינוי אחד הצדדים.

8 · Diagnostics

8 · אבחון

  1. Log page first. It shows the 20 newest events with a timestamp, and the sequence records every state transition. A fault entry carries the failing step's text.
  2. Tick Debug on the Log page to add every robot frame sent and received. Untick it afterwards — the ring is only 20 entries and debug traffic fills it in seconds.
  3. Robot page for the link: connection state, packets in and out, the last frame each way, and the two numbers actually being exchanged.
  4. If the link says Connected, packets are climbing, and yet no cycle ever starts — check what Last Rx says. A reply that is not a CMD: frame means the robot software does not implement the state channel.
  5. The timestamps are only as good as the panel clock. If it shows --:--:-- the clock is unset, which is honest rather than wrong.
  1. קודם כל מסך היומן. הוא מציג את 20 האירועים החדשים עם חותמת זמן, והרצף מתעד כל מעבר מצב. רשומת תקלה מכילה את הטקסט של השלב שנכשל.
  2. סמן Debug במסך היומן כדי להוסיף כל מסגרת רובוט שנשלחה והתקבלה. בטל את הסימון לאחר מכן — הטבעת מכילה 20 רשומות בלבד ותעבורת ניפוי ממלאת אותה בשניות.
  3. מסך הרובוט לבדיקת הקישור: מצב חיבור, מנות נכנסות ויוצאות, המסגרת האחרונה בכל כיוון, ושני המספרים שמוחלפים בפועל.
  4. אם הקישור מציג Connected, המנות עולות, ובכל זאת אף מחזור לא מתחיל — בדוק מה מציג Last Rx. תשובה שאינה מסגרת CMD: פירושה שתוכנת הרובוט אינה מיישמת את ערוץ המצב.
  5. חותמות הזמן טובות כמו שעון הפאנל. אם מוצג --:--:-- השעון לא כוון — זה כנה ולא שגוי.
Bench test scripts

scripts/pb_test/pb_test_procedure.py exercises all three buttons in every machine state over ADS and writes an HTML report (57 checks). scripts/pb_test/cycle_trace.py runs one complete cycle with the pistons emulated and checks the coil pattern of every state. Neither may be pointed at a machine with air connected.

סקריפטים לבדיקה בשולחן

scripts/pb_test/pb_test_procedure.py בודק את שלושת הלחצנים בכל מצבי המכונה דרך ADS וכותב דוח HTML (57 בדיקות). scripts/pb_test/cycle_trace.py מריץ מחזור שלם עם בוכנות מדומות ובודק את תבנית הסלילים בכל מצב. אין להפנות אף אחד מהם למכונה עם אוויר מחובר.

  3. Fetch it over FTP. Type ftp://<panel-ip>/Logs/ into Windows Explorer — for example ftp://192.168.1.100/Logs/. No user name or password. Drag the file off and open it in Excel.
  4. Untick it when you are done unless the machine is meant to keep logging.
The panel can switch it on but cannot show you whether it is working

The checkbox is the only file-log control on the panel. The status fields — current file, bytes written, files on disk, and any error — are only on FlowerPyHmi or over ADS. What the panel does show is a failure: a write error puts one ERR line in the Log list, so if logging has stopped working you will see it there.

One file a day, and old ones are deleted for you

A new file starts each day. If one day gets busy the file rolls at 512 KB into flower-YYYY-MM-DD_002.csv, _003 and so on. Once the folder passes 16 MB the oldest files are deleted automatically, so it cannot fill the card. Those three limits are adjustable, but only from FlowerPyHmi.

A row saying “entries lost” is real, and is telling you the truth

Under a heavy burst the machine can produce log entries faster than they reach the card, and the oldest are overwritten before they are written out. When that happens the file itself gets a line like 312 entries lost - CSV writer fell behind the ring at the point where the gap is. Treat it as a genuine hole in the record, not as a fault in the logger.

Never point the log folder outside \Hard Disk\

The folder is set by sDir and must stay under \Hard Disk\, which is the Compact Flash. \Temp\ and the drive root \ also accept files, but they live in RAM and are emptied on every restart — so logging would appear to work perfectly and then lose everything on the one event you wanted it for.

10 · Commissioning notes

10 · הערות הרצה ראשונית

  • The robot IP is persistent. Changing the default in the source does not retarget a panel that has already run — the stored value wins. Use the Robot screen.
  • Turn off both bench flags (bNoSensors, bBypassPlateSensors) before production. They persist.
  • Never merge the bench target configuration. The local development setup disables the fieldbus; shipping it would give the machine a build with no IO.
  • A full cycle on real sensors has never been run. Every test so far used emulated or bypassed sensors. Expect the first real cycle to reveal timing that needs tuning.
  • כתובת ה-IP של הרובוט נשמרת. שינוי ברירת המחדל בקוד אינו מפנה מחדש פאנל שכבר רץ — הערך השמור קובע. השתמש במסך הרובוט.
  • כבה את שני דגלי השולחן (bNoSensors, bBypassPlateSensors) לפני ייצור. הם נשמרים.
  • לעולם אל תמזג את תצורת יעד השולחן. סביבת הפיתוח המקומית מנטרלת את אפיק השדה; שליחתה תיתן למכונה גרסה בלי IO.
  • מחזור שלם על חיישנים אמיתיים מעולם לא הורץ. כל הבדיקות עד כה השתמשו בחיישנים מדומים או מבוטלים. צפה שהמחזור האמיתי הראשון יחשוף תזמונים שדורשים כיול.
