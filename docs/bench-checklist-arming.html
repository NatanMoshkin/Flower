Before this build ever goes back to the real machine

167_01_Saad_PLC.tsproj is currently rewritten for this bench: TargetNetId points at 5.79.93.36.1.1 and the EtherCAT device is Disabled="true". That is correct here and must not be committed — deploying it to the machine would run the PLC with no fieldbus at all. Re-enable the device and retarget, or git checkout the file, before you go back.

What this run cannot tell you

No real IO. Every piston sensor is simulated by timers, so this proves sequence, arming, protocol and logging — not wiring, not travel times, not the plate sensors. Physical jog and lamp-wiring checks are marked machine only and are expected to be blocked here.

Expect
→ NOT_HOMED. This is new behaviour, slightly beyond the original ask: it gives the operator a way to take the machine out of the robot's reach. Flag it if you'd rather STOP did nothing from IDLE.

Fault recovery — unattended, robot-driven

F1

Provoke a real fault

Do
Un-tick Bypass plate sensors, arm, then let the mock start a cycle. With no plate sensors wired, WAIT_PLATE will time out.
Expect
ERR, iErrorCode 9, text WAIT_PLATE timed out (plate never arrived). red on green off

F2

RESET homes — it does not jump to IDLE

Do
Watch what the robot's CMD:2 produces. Touch nothing.
Expect
Log reads ERR -> INIT_PUSH_RETRACTING — not ERR -> IDLE. Then the chain to IDLE. A fault leaves the pistons in unknown positions, so advertising STATE:0 immediately would claim "ready" while it is not.
F3

Recovery completes with no operator action

Do
Keep watching. Re-tick Bypass plate sensors so the next cycle can pass.
Expect
Full loop unaided: ERR → STATE:99 → CMD:2 → clear + home → STATE:0 → CMD:1 → next bulb. Nobody pressed anything. iErrorCode back to 0.

Expect
Same homing path. Operator and robot resets share one consumption path, so they cannot diverge.
