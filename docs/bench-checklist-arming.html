A2

A well-behaved robot waits

Do
Leave the mock in AUTO and wait 30 s.
Expect
Mock keeps answering CMD:0; panel stays NOT_HOMED, nCyclesCompleted unchanged, no External start pulse in the log.
Note what this does and does not prove. In AUTO the mock only asks when it sees STATE:0, so this confirms the protocol contract — nothing more. The PLC's own gate is A2b.
A2b

A badly-behaved robot is refused the real gate test

Do
Restart the mock as python scripts/mock_robot/mock_robot.py --force-start — it answers every state with CMD:1, including NOT_HOMED. Leave the panel un-armed.
Equivalent without the mock: write (or Force) GVL_Robot.stParams.nRobotCmd := 1 from TcXaeShell.
Expect
The log does show External start pulse — repeatedly — because the FB logs it unconditionally before the state machine runs. And eStep stays NOT_HOMED with nothing moving, nRobotCmd snapping back to 0.
That pairing is the proof: the command genuinely arrived, was seen, and was refused. "Nothing happened" on its own cannot distinguish a working gate from a robot that never asked. This is the power-up hazard being closed — before this change the same command started a cycle with the pistons anywhere.

Refused in both. Manual is gated by bMachineAuto; ERR is not IDLE so the exit condition is never reached. Put the mock back to AUTO before A3.

Do
Watch what the robot's CMD:2 produces. Touch nothing.
Expect
Log reads ERR -> INIT_PUSH_RETRACTING — not ERR -> IDLE. Then the chain to IDLE. A fault leaves the pistons in unknown positions, so advertising STATE:0 immediately would claim "ready" while it is not.

Full loop unaided: ERR → STATE:99 → CMD:2 → clear + home → STATE:0 → CMD:1 → next bulb. Nobody pressed anything. iErrorCode back to 0.
