Push-button test report

Every documented behaviour of the three panel push buttons and their LEDs, exercised against a live PLC over ADS. Presses are simulated by writing the raw input channels GVL_IO.dIn[13..15]; every other value is read back from the PLC, including the solenoid coil outputs.

All checks passed. This covers the LED wiring, the three Manual jogs, the un-armed and armed Automatic states, the ERR jog window, and recovery — including the negative cases, which are the ones that prove the gates actually gate.

What this run cannot tell you

No physical I/O. The EtherCAT device is disabled on this bench target, so a “press” is a memory write and a “coil” is a memory read. The button contacts, the LED lamps, the valve wiring and the air circuit are all still unverified — that is field checks FLD1 – FLD4 in docs/bench-checklist-arming.html.

The ERR jog window is wider here than on the machine. This run disables GVL_Robot.bTcpEnable, so nothing answers STATE:99 with CMD:2 and ERR stays latched indefinitely. With a live robot the PLC clears the fault and homes about a second after entering ERR, so group E proves the jog works, not that an operator will get the chance to use it.
